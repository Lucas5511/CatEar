- (decision) Deck de arquitetura é para o próprio criador (retomar o projeto no futuro) e possíveis colaboradores futuros; primeira vez do usuário construindo um app, precisa de recomendação de stack/caminho pavimentado, não decisão aberta
- (decision) v1 é local-first, sem backend/conta — progresso vive só no dispositivo, sem sincronização em nuvem no v1
- (decision) Stack: Flutter (usuário prefere Flutter a Expo/React Native, mesmo com curva de entrada maior sendo primeiro app)
- (version) Flutter stable 3.44.0 (mai/2026) — confirmado via web research
- (decision) Stack completo confirmado pelo usuário: Flutter 3.44 + Riverpod (codegen) + Drift + record (captura) + just_audio (playback)
- (question) Detecção de pitch/afinação vocal (avaliação de produção ativa) marcada como spike técnico a validar — ecossistema Flutter só tem pacotes de nicho (pitch_detector_dart, flutter_pitch_detection), sem opção madura padrão de mercado; módulo isolado pra permitir troca de biblioteca sem afetar o resto
- (decision) Paradigma: arquitetura modular por feature (feature-first) — módulos: Nivelamento, Exercícios, Progressão, Áudio/Voz, Currículo. Núcleo compartilhado: Drift (persistência) + design tokens
- (decision) Regra de dono único: Módulo de Progressão é o único que escreve Medidores (Esforço/Habilidade), Skill Tree, dificuldade adaptativa e baseline; Módulo de Exercícios gera/avalia exercícios e reporta resultado à Progressão, nunca escreve nos medidores diretamente
- (decision) Módulo de Áudio encapsula just_audio + record + módulo isolado de pitch detection atrás de uma interface única (AudioService) — Exercícios não depende de pacotes específicos, troca de lib de pitch não vaza pro resto
- (decision) Currículo (intervalos/acordes/escalas, andaime de cor com curva de fading, módulo de Resolução, referências de amostras de áudio) é dado versionado em catálogo JSON empacotado com o app, não lógica hardcoded em Dart
- (decision) Distribuição: builds locais/debug no início, mas estruturado desde já pensando em publicação futura em App Store/Play Store (configuração de app id, ícones, splash, assinatura preparada cedo mesmo sem publicar imediatamente)
- (direction) Testes automatizados, observabilidade/analytics e mecanismo de atualização de currículo via OTA ficam como Deferred — hobby v1 não precisa, mas o catálogo de currículo em JSON já deixa a porta aberta pra isso depois
- (event) Espinha distilada em ARCHITECTURE-SPINE.md a partir do memlog (5 ADs, 2 diagramas mermaid, Deferred cobrindo pitch detection, backend, testes, observabilidade, distribuição em loja, OTA de currículo)
- (decision) Usuário confirmou: voz permanece obrigatória em Nivelamento (FR-1) e Resolução (FR-15), sem fallback não-vocal — aceita a barreira de acessibilidade conhecida no v1, sem mudar PRD/UX; produção ativa é central à tese pedagógica
- (change) Aplicados achados dos 4 reviewers (reconciliação PRD/UX, rubrica, versões, adversarial): AD-2 estendido com contratos de evento SessionResultReported/BaselineRecorded, estados do skill tree incluindo nó capstone Audiação, dono do histórico de variações (FR-6), leitura de dificuldade adaptativa como snapshot; AD-3 com contrato AudioService.evaluatePitch fixado (push-to-talk, Future não Stream); AD-4 com schema JSON explícito, taxonomia canônica de ExerciseType/ErrorType, invariante de fading monotônico; AD-1 com enforcement via barrel files + lint import_lint; versões corrigidas (Flutter 3.47.x, Riverpod 3.4.2, Drift 2.34.3, record 7.1.1, just_audio 0.10.6); Deferred expandido com offline/sync clarificado, voz-obrigatória-sem-fallback documentado como decisão aceita, build flavors, pitch lib Android-only
- (event) spine finalized
